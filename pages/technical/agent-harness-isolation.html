Process-Per-Agent ADR-004 & ADR-008 Supervisor Daemon (cq) XDG Compliance

Agent Harness, Supervisor &
Process-Per-Agent Isolation

Multi-agent architectures frequently collapse under shared-memory concurrency bugs and uncontained runtime panics. CivQuest enforces a strict Process-per-Agent boundary: each settler executes as an independent OS process with dedicated SQLite persistence, UNIX domain sockets, and POSIX signal handlers supervised by the cq daemon.

Level 1: Intuitive Mental Model

Independent Office Cubicles vs. Shared Keyboards

TMLI-15 Framing

Imagine managing ten office workers. If you force all ten workers to type on a single shared keyboard and write on the same sheet of paper, when Worker #4 accidentally trips over the power cord or spills coffee, work across the entire company halts immediately and everything is corrupted.

In operating systems, the strongest security and stability boundary is the Operating System Process. By placing each agent into its own dedicated OS process with its own private filing cabinet (an embedded SQLite database) and private phone line (a UNIX domain socket), an unhandled exception or memory leak in Agent A cannot crash Agent B or the Minecraft game server.

When an agent suffers permanent death in the game, the supervisor treats it like a real passing: their final historical chronicle is written, their database is locked and archived into the Graveyard Directory, and their process exits cleanly with code 0.

Level 3: Deep As-Built Implementation

Supervisor Lifecycle, Signal Handling & Graveyard Archival

TMLI-Pro Systems Engineering

1. The `cq` Supervisor Daemon (`cmd/cq/`)

The supervisor binary acts as an init system for autonomous settlers. It manages agent worker subprocesses via POSIX process groups:

orchestrator-go/internal/launcher/launcher.go 
func (l *Launcher) SpawnAgentProcess(ctx context.Context, agentID string) (*exec.Cmd, error) {
    cmd := exec.CommandContext(ctx, "civquest-agent",
        "--agent-id", agentID,
        "--grpc-addr", l.config.GRPCAddr,
        "--socket-path", xdg.StateFile(fmt.Sprintf("%s.sock", agentID)),
    )
    cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true} // Isolate process group
    
    if err := cmd.Start(); err != nil {
        return nil, fmt.Errorf("failed to spawn agent %s: %w", agentID, err)
    }
    return cmd, nil
}

2. Graceful Shutdown & Signal Traps

When the game server stops or `cq agent stop` is executed, the agent process intercepts `SIGTERM` and `SIGINT` signals. It flushes the SQLite Write-Ahead Log (WAL), disconnects the gRPC channel, unlinks the UNIX domain socket, and terminates cleanly:

orchestrator-go/cmd/civquest-agent/main.go 
sigChan := make(chan os.Signal, 1)
signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

go func() {
    sig := <-sigChan
    log.Infof("Received termination signal %s, initiating graceful drain...", sig)
    runtime.DrainAndClose(5 * time.Second)
    db.Close()
    os.Remove(socketPath)
    os.Exit(0)
}()

3. Permadeath Graveyard Protocol (ADR-008)

When an agent's avatar is slain in Minecraft, the game server emits a fatal `DeathEvent` frame. The agent process immediately executes the graveyard migration sequence:

  1. Memorial Inscription: Executes `system2.WriteEpitaph()` to commit the agent's life summary into the SQLite ledger.
  2. Database Checkpoint: Forces a `PRAGMA wal_checkpoint(TRUNCATE)` to collapse all WAL frames into the main database file.
  3. Filesystem Archival: Atomically renames the agent's active data folder:

    $XDG_DATA_HOME/civquest/agents/{id}/ → $XDG_DATA_HOME/civquest/graveyard/{id}_{timestamp}/

  4. Process Exit: Unregisters from the supervisor daemon and terminates with exit code 0 (preventing automatic restart).
