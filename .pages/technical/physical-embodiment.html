Physical Embodiment, Avatars &
Spatial Voxel Navigation

Embodied simulation demands physical fidelity: gravity, hitbox collisions, reach distances, and tool degradation. CivQuest manifests agents as server-side FakePlayer avatars, injects dynamic client skin packets without Mojang auth, delegates physical pathfinding to an integrated Baritone API wrapper, and coordinates multi-agent construction via spatial quadrant partitioning.

Physical Grounding & Multi-Agent Construction Challenges

In a physical world, an agent cannot simply wish a building into existence or teleport through walls. To place a brick, the agent must physically walk over to the site, possess the brick in their inventory, stand within reach distance, and make sure they aren't standing in the exact spot where the brick is about to be placed.

When multiple builders work on the same house simultaneously, two major failure modes occur:

  • Physical Collisions: If four builders try to work on the same corner block at the same time, they push each other into hazards or get stuck in narrow doorways.
  • Entombment (Trapped Inside Walls): If a builder places the roof before finishing the walls, or builds a wall while standing inside it, they trap themselves and starve.

CivQuest solves this by organizing construction like a real-world civil engineering project: the plot is divided into four spatial quadrants ($NW, NE, SW, SE$), and building proceeds strictly from the bottom up ($Y_{\text{min}} \to Y_{\text{max}}$). Each builder is assigned an exclusive sector so they never collide.

Spatial Quadrant Partitioning Architecture

Collaborative multi-agent construction maps out discrete 3D voxel coordinate assignments across non-overlapping sectors. Elevation layers synchronize at each height step before builders ascend.

Spatial Quadrant Invariants

Sector Locking: No builder may place or break blocks outside their designated quadrant ($NW, NE, SW, SE$).

Elevation Synchronization: All quadrants must synchronize layer completion at elevation $Y$ before any agent is permitted to place blocks at $Y+1$.

Entrapment-Free Construction Guarantee

By enforcing bottom-up vertical layering ($Y_{\text{min}} \to Y_{\text{max}}$) and spatial quadrant boundaries ($NW, NE, SW, SE$), multi-agent construction projects guarantee zero builder entombment and zero voxel overwrite race conditions.

FakePlayer Internals, Skin Packets & Baritone A* Search

1. Server-Side AgentEntity Architecture (AgentEntity.java)

Settler avatars inherit directly from net.minecraft.server.level.ServerPlayer. They are headless server-side player instances with standard player dimensions ($0.6\text{m} \times 1.8\text{m}$), eye heights, gravity vectors, and inventory equipment slots:

public class AgentEntity extends ServerPlayer { private final String agentId; private final UUID offlineUuid; private final BaritoneWrapper pathfinder; public AgentEntity(MinecraftServer server, ServerLevel level, GameProfile profile, String agentId) { super(server, level, profile, ClientInformation.createDefault()); this.agentId = agentId; this.offlineUuid = UUID.nameUUIDFromBytes(("CivQuest:" + agentId).getBytes(StandardCharsets.UTF_8)); this.pathfinder = new BaritoneWrapper(this); } }

2. Dynamic Packet Skin Injection without Mojang Authentication

Standard Minecraft servers fetch player skins via Mojang's authentication session servers. Because CivQuest agents are offline-generated entities, the server mod injects skin metadata directly into the player tab list and entity tracker packets:

  1. The agent spawn request transmits raw 64x64 RGBA PNG bytes or a signed Mojang texture property payload (SpawnAgentRequest.skin_texture_value).
  2. AgentSkinManager.java populates the GameProfile property map with textures key-value pairs.
  3. The server broadcasts ClientboundPlayerInfoUpdatePacket.Action.ADD_PLAYER to all connected clients, causing clients to render custom skins immediately.

3. Baritone A* Pathfinding Integration

Rather than relying on basic mob navigation meshes, CivQuest embeds Baritone's full voxel A* search engine. The wrapper supports complex 3D maneuvers:

  • Dynamic Parkour: Sprint-jumping across 3-block chasms and jumping up 1-block stone steps without placing scaffolding.
  • Obstacle Clearance: Automatically breaking obstructing leaves or cobwebs if a path cannot be found within 400 iterations.
  • Safety Invariants: Baritone costs penalize lava ($+10,000$), deep water ($+500$), and fall damage heights greater than 3 blocks ($+1,000$).

See: Werfel, J., Petersen, K., & Nagpal, R. (2014). Designing collective behavior in a billion-robot swarm. Science, 343(6172), 754–758.
