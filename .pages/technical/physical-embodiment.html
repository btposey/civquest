Avatar Embodiment &
Spatial Voxel Navigation

Embodied simulation demands physical grounding: gravity, bounding box collisions, reach envelopes, and tool degradation. CivQuest manifests autonomous agents as server-side avatars, broadcasts dynamic skin packets without external authentication dependencies, and executes voxel traversal via an integrated A* heuristic pathfinding engine.

Physical Grounding & Kinematic Locomotion

In an embodied physical environment, intelligence is bounded by spatial constraints.[1] An agent cannot teleport across barriers or place blocks instantaneously. To manipulate the world, the avatar must physically traverse irregular terrain, manage momentum and fall velocity, stand within reach range, and maintain line-of-sight clearance.

Simulating autonomous settlers alongside human players introduces three core architectural requirements:

  • Physics and Hitbox Parity: Settler avatars must possess identical bounding boxes, eye levels, jump physics, and inventory mechanics as vanilla players to prevent unfair advantages or physics glitches.
  • Offline Visual Identity: Agents must display distinct humanoid skins and clan cloaks without requiring active authentication sessions with external servers.
  • 3D Voxel Pathfinding: Unlike standard mobs restricted to pre-baked navigation meshes, settlers must navigate arbitrary dynamic voxel structures, sprint-jump across chasms, step up elevation changes, and clear obstructing blocks when necessary.

Avatar Architecture & Sensory-Kinematic Loop

The avatar executes within the server tick loop, bridging motor intents from the orchestrator into physical in-engine actions while streaming sensory frustum frames back to the cognitive harness.

Physical Embodiment Invariants

Server-Side Execution: All avatar physics, item interactions, and block placements execute server-side through standard player entity APIs, ensuring complete compatibility with vanilla game mechanics.

Reach & Collision Envelopes: Block interactions strictly enforce the 4.5-block reach radius and raycast visibility checks, preventing out-of-reach block modifications.

Physical Parity Guarantee

By subclassing server player entities, autonomous avatars remain subject to identical gravitational acceleration, breath meters, fall damage, and reach distances as human players, preserving fair gameplay simulation.

Subsystem Mechanics, Packet Distribution & A* Heuristic

1. Server-Side Avatar Entity Architecture

Settler avatars inherit directly from the server player base class.[3] They are headless server-side player instances with standard player dimensions, eye heights, gravity vectors, and inventory equipment slots. To ensure stability across world reloads, each avatar's offline UUID is generated deterministically from its unique agent identifier using a standard namespaced hash.

2. Dynamic Packet Skin Injection without Authentication

Standard game servers fetch player skin textures by querying external session servers. Because autonomous agents are offline-generated entities, the server mod injects skin metadata directly into the player tab list and entity tracker packets:[4]

  1. The agent spawn request transmits raw 64x64 texture bytes or signed texture property strings.
  2. The skin manager populates the game profile property map with the corresponding texture key-value pairs.
  3. The server broadcasts player info update packets to all connected clients, instructing clients to render the custom skin immediately without network lookups.

3. Baritone A* Pathfinding Heuristic & Cost Modeling

Rather than relying on basic mob navigation meshes, the architecture embeds an integrated A* voxel search engine.[2] The pathfinder evaluates total traversal cost for each candidate voxel node:[5]

f ( n ) = g ( n ) + h ( n ) + C break ( n ) + C hazard ( n )

Where h(n)=∥Pn−Pgoal∥2 represents Euclidean goal distance, Cbreak(n) models hardness penalties for clearing obstructing blocks, and Chazard(n) penalizes hazardous voxels such as lava, deep water, or dangerous fall distances.
