Agent Harness, Supervisor &
Process-Per-Agent Isolation

Multi-agent architectures frequently collapse under shared-memory concurrency bugs and uncontained runtime panics. CivQuest enforces a strict Process-per-Agent boundary: each settler executes as an independent OS process with dedicated SQLite persistence, UNIX domain sockets, and POSIX signal handlers supervised by the cq daemon.

Independent OS Processes vs. Shared-Memory Concurrency

Imagine managing ten office workers. If you force all ten workers to type on a single shared keyboard and write on the same sheet of paper, when Worker #4 accidentally trips over the power cord or spills coffee, work across the entire company halts immediately and everything is corrupted.

In operating systems, the strongest security and stability boundary is the Operating System Process. By placing each agent into its own dedicated OS process with its own private filing cabinet (an embedded SQLite database) and private phone line (a UNIX domain socket), an unhandled exception or memory leak in Agent A cannot crash Agent B or the Minecraft game server.

When an agent suffers permanent death in the game, the supervisor treats it like a real passing: their final historical chronicle is written, their database is locked and archived into the Graveyard Directory, and their process exits cleanly with code 0.

Fault-Isolated Process Supervision & Process Tree Architecture

The multi-process architecture guarantees clean blast-radius containment. The cq supervisor daemon monitors worker health, aggregates cluster telemetry, and coordinates process spawning and shutdown.

Process Boundary Invariants

Thread Isolation: No Go process may spawn goroutines representing more than one agent identity. Multi-agent thread loops within a single process are strictly prohibited.

IPC Boundary: All inter-agent data flow must traverse external network or socket IPC channels.

Filesystem Compliance: Hardcoded paths are strictly forbidden. All state, data, and configuration paths must resolve via standard XDG Base Directory environment variables.

Blast-Radius Containment Guarantee

By enforcing process-level isolation, sudden panics, memory leaks, or unhandled exceptions in experimental LLM agent loops remain strictly contained, ensuring 100% continuous uptime for the game server and surviving settlers.

2. Graceful Shutdown & Signal Traps

When the game server halts or an administrator requests agent deactivation, the worker intercepts termination signals.[4] It executes an atomic draining routine: flushing Write-Ahead Log frames to disk, closing open gRPC streams, unlinking runtime domain sockets, and terminating cleanly within a bounded five-second window.

3. Permadeath Graveyard Protocol

When an agent's avatar is slain, the game server emits a fatal death event notice. The agent process immediately executes the graveyard migration sequence:

  1. Memorial Inscription: Commits the agent's life summary and dynastic achievements into the local relational ledger.
  2. Database Checkpoint: Forces a full WAL truncation checkpoint to collapse all journal frames into the primary database file.
  3. Filesystem Archival: Atomically moves the agent's active data directory into the graveyard archive path, updating permissions to read-only.
  4. Process Exit: Unregisters from the supervisor daemon and terminates with exit code zero to prevent automatic process resurrection.
