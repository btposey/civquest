Networked IPC Streaming &
Bounded Control Channels

Decoupling simulation physics from agent cognition requires a high-throughput, low-latency inter-process communication bridge. CivQuest implements bidirectional gRPC streaming over Netty and UNIX Domain Sockets, utilizing typed SlotQueue coalescing to prevent queuing deadlocks and stale kinematic latency.

The Dual-Requirement Problem: Continuous Kinematics vs. Discrete Mutations

Imagine driving a car while a passenger gives you navigation instructions. If you ask "Where do I turn?" and there is a 5-second radio delay, hearing an old message that says "Turn left now!" after you have already passed the intersection will cause you to drive off the road. For continuous movement, old directions are worse than useless—they are actively dangerous. You only ever want the freshest steering direction.

Now imagine building a brick wall with supplies sent through a pneumatic tube. If the pipe drops Brick #3 because it arrived too quickly, the wall will have a hole in the middle and collapse. For physical construction, every single brick placement must arrive in strict, exact order without skipping.

A single standard network queue cannot handle both problems simultaneously. If you use a strict FIFO queue, outdated walking directions accumulate during lag spikes, causing the agent to wander around like a ghost. If you drop packets aggressively, building projects break. CivQuest solves this dilemma using a Typed SlotQueue: kinematic vectors overwrite stale data instantly, while discrete construction intents wait in a reliable FIFO sequence.

Intent Coalescing & Buffer Backpressure Architecture

The orchestrator streams mixed continuous kinematic vectors (target waypoints, head pitch/yaw) and discrete voxel state mutations (place block, equip sword, chat) across the IPC boundary at 5 Hz.

Queue Invariant & Latency Bounds

Kinematic Intent Slots (Navigate / Look): Hard capacity of 1. New updates immediately overwrite unconsumed goals (zero queue delay).

Discrete Action Queue (Voxel Placements / Attacks): Strict FIFO order preservation bounded to 64 operations before triggering backpressure throttling.

Kinematic Fidelity Guarantee

By demultiplexing lossy vector overwrite slots from lossless action queues, the system eliminates rubber-banding and pathing oscillation without sacrificing 100% block-placement order fidelity.

Protobuf Specifications & Transport Mechanics

1. The gRPC Streaming Contract (civquest.proto)

The central communication bridge is defined as a bidirectional streaming RPC in proto/civquest/v1/civquest.proto. Every active agent holds exactly one persistent stream throughout its process lifecycle:

service CivQuestBridgeService { // Primary per-agent bidirectional control and telemetry stream rpc ConnectAgent(stream AgentIntent) returns (stream TelemetryFrame); // Administrative RPCs invoked by cq supervisor rpc SpawnAgentEntity(SpawnAgentRequest) returns (SpawnAgentResponse); rpc DespawnAgentEntity(DespawnAgentRequest) returns (DespawnAgentResponse); }

2. Typed SlotQueue Coalescing Implementation

To prevent kinematic queue deadlocks while preserving construction fidelity, the Go harness (internal/bridge/slot_queue.go) implements a multi-slot buffer structure:

type SlotQueue struct { mu sync.Mutex navSlot *civquestv1.NavigateIntent // Lossy: latest overwrites previous lookSlot *civquestv1.LookAtIntent // Lossy: latest overwrites previous actionQueue []*civquestv1.ActionIntent // Lossless FIFO: bounded capacity 64 chatQueue []*civquestv1.ChatIntent // Lossless FIFO: bounded capacity 16 intentStream chan *civquestv1.AgentIntent } func (q *SlotQueue) PushNavigate(intent *civquestv1.NavigateIntent) { q.mu.Lock() defer q.mu.Unlock() q.navSlot = intent // Overwrite immediately } func (q *SlotQueue) PushAction(intent *civquestv1.ActionIntent) error { q.mu.Lock() defer q.mu.Unlock() if len(q.actionQueue) >= 64 { return ErrActionQueueFull // Triggers backpressure throttle } q.actionQueue = append(q.actionQueue, intent) return nil }

3. Shared-Key HMAC-SHA256 Authentication

When operating across remote hosts or untrusted local networks, the gRPC stream enforces cryptographic authentication. Both the NeoForge mod (CivQuestAuthInterceptor.java) and the Go client compute a message authentication code over the payload timestamp and agent UUID:

Token = HMAC-SHA256(K_shared, AgentUUID || TimestampEpochMs)

The token is transmitted in the gRPC metadata header (x-civquest-auth-token). Tokens with timestamps drifting by more than $\pm 5000\text{ ms}$ are immediately rejected with Status.UNAUTHENTICATED to defend against replay attacks.

Footnotes & Conceptual Provenance
  1. Head-of-Line Blocking and Queuing Latency in Real-Time Control: In classical queueing theory (Little's Law), buffering continuous kinematic sensor readings in standard FIFO queues introduces artificial phase lag proportional to queue depth ($\bar{T} = \bar{N} / \lambda$). Lossy overwrite registers (SlotQueues) maintain zero latency accumulation by ensuring the consumer always reads the instantaneous system state. See: Kleinrock, L. (1975). Queueing Systems, Volume 1: Theory. John Wiley & Sons.
  2. Reactive Stream Backpressure & Flow Control: Bounded ring buffers with explicit token-bucket or drop-tail strategies prevent unbounded heap growth and GC pressure under network starvation or CPU throttling. See: Reactive Streams Specification (v1.0.4), http://www.reactive-streams.org.
  3. Time-Bounded HMAC Replay Protection: Cryptographic message authentication codes over concatenated monotonic timestamps protect inter-process RPC channels from packet injection and replay attacks across untrusted transport networks. See: Krawczyk, H., Bellare, M., & Canetti, R. (1997). HMAC: Keyed-Hashing for Message Authentication. RFC 2104.
