Hierarchical State Machine &
Intent Actuation Pipeline

Unconstrained priority cascades produce erratic agent behaviors, race conditions, and illegal state transitions. CivQuest replaces ad-hoc rule scoring with a formal Hierarchical Finite State Machine (HFSM), enforcing strict transition guards, entry/exit queue purging, and inventory-gated ghost intent pruning.

Eliminating Behavioral Race Conditions & Ghost Actions

Imagine an autonomous robot designed to explore an island. If you program it with a list of independent rules—like "If it's night, go to sleep" and "If a predator attacks, run away"—what happens when a predator attacks at 9:01 PM? Without a structured state machine, the clock rule might override the combat rule, causing the robot to lie down and take a nap while actively being attacked.

A formal State Machine acts like an air traffic controller. You cannot transition from Fleeing Combat to Sleeping in Bed unless a strict security checkpoint is cleared (the hostile threats must be dead or out of range, and the agent must be inside an enclosed shelter).

Furthermore, consider "Ghost Intents": if an agent panics and streams "Raise Shield!" fifty times per second across the network, but their backpack contains no shield, the game engine wastes CPU processing empty commands while network buffers fill with garbage. CivQuest validates physical prerequisites before emitting intents, ensuring every packet sent across the wire produces real physical effects.

Formal State Integrity & Invariant Transition Guards

State machines in high-frequency embodied loops must prevent illegal transitions and race conditions between competing tactical goals. CivQuest structures agent behavior as a deterministic Hierarchical Finite State Machine with explicit entry and exit actions.

State Guard Invariants

Transition Validation: Every state transition must evaluate a boolean guard condition. Unchecked transitions are strictly forbidden.

Emergency Queue Flushing: Transitioning into EMERGENCY must immediately flush all non-combat navigation and action queues.

Rest Invariant: REST is strictly unreachable while ThreatCount > 0 or SurvivalConfidence < 0.70.

Behavioral Stability Guarantee

By enforcing transition guards and entry/exit queue purging, the HFSM guarantees deterministic state progression, eliminating navigation goal thrashing and mid-combat sleeping bugs.

During active pathing in exploration or shelter routines, dynamic voxel obstructions or pathfinder divergence can cause the avatar to stall. The harness monitors spatial displacement across sliding temporal windows:[5]

D progress = ∑ k = 0 N − 1 ∥ P t − k − P t − k − 1 ∥ 2 < 0.50 blocks, N ≥ 10

Upon detecting a stall condition, the exit purger resets the active pathing target, issues a lateral evasive step, and selects an alternative exploration vector offset by ninety degrees.

Footnotes & Conceptual Provenance
  1. Hierarchical Statecharts and Guard Formalism: David Harel's statechart formalism introduced hierarchy, orthogonality, and entry/exit action semantics to classical Mealy/Moore finite state machines, preventing exponential state explosion in complex reactive systems. See: Harel, D. (1987). Statecharts: a visual formalism for complex systems. Science of Computer Programming, 8(3), 231–274.
  2. Behavior Trees vs. Hierarchical FSMs in Autonomous Robotics: While Behavior Trees offer modular composability, formal HFSMs with explicit boolean guards guarantee deterministic state invariants and instantaneous priority preemption under acute survival emergencies. See: Colledanchise, M., & Ögren, P. (2018). Behavior Trees in Robotics and AI: An Introduction. CRC Press.
