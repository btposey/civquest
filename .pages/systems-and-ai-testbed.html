The Tripartite Latency Hierarchy

Allocating compute and perception across three neurological tiers to maximize survival and goal throughput.

⚡

Layer 1A: Peripheral Reflexes

Spinal Cord Analog: Synchronous, in-engine Java execution (20 Hz, <0.1ms, 0 IPC delay). Resolves sub-tick physical emergencies (shield raising on projectile trajectory intersection, item vacuuming, obstacle climbing) and emits ascending ReflexNotice events.

🧠

Layer 1B: Tactical Intuition

Basal Ganglia Analog: External deterministic Go utility AI (5 Hz, <5ms, 0 LLM tokens). Evaluates threat matrices, runs the Hierarchical Finite State Machine (HFSM), manages inventory slots, and streams kinetic intents through a bounded slot queue.

🏛️

Layer 2: Strategic Cognition

Prefrontal Cortex Analog: Asynchronous LLM inference (Ollama/vLLM) and vector RAG (sqlite-vec). Generates structured goal directives (trade bargains, blueprint layouts, historical chronicles) that parameterize active HFSM states.

Architectural Invariants & Complexity Control

Disciplined engineering patterns replacing fragile prompt chaining with deterministic state guarantees.

⚙️

Hierarchical State Machine (HFSM)

Replaces unconstrained priority cascades with an explicit state graph (BOOTSTRAP, EXPLORE, SHELTER, EMERGENCY, REST). Gated transitions guarantee that combat panic is never preempted by temporal routines like sleep.

🔄

Afferent Perception-Action Loops

When in-engine reflexes fire, lightweight ReflexNotice telemetry reports upward to the Go harness. Tactical evaluators immediately adjust survival confidence scores and replan tasks without waiting for an active goal to fail.

📦

Typed SlotQueue Intent Coalescing

High-frequency kinetic vectors (navigation, combat attacks) are bounded and coalesced so only the freshest target vector transmits, while sequential block placement intents retain strict FIFO order for structural integrity.

🎯

Ghost Intent Elimination

Prerequisite inventory guards validate equipment (HasShield, HasWeapon) before emitting combat directives, eliminating zero-effect gRPC payload transmissions that waste network bandwidth.

🔒

Process-Per-Agent Isolation

Each agent executes in an isolated OS process (civquest-agent) with dedicated XDG directories, SQLite databases, and UNIX domain sockets. Process failures are isolated and never crash neighboring agents or the game server.

🧪

Spatial Simulation Testbed

Purpose-Built for Minecraft: Rather than forcing premature hardware abstraction layers, CivQuest leverages Minecraft's voxel grid as a high-fidelity sandbox to validate systems engineering principles—yielding transferable wisdom for future physical embodied systems.
